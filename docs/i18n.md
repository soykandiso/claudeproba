# Languages

How a page knows its language, how a string becomes translatable, and what is left to mark.
Built in roadmap P3 s40 (07.10.2026); the code is `app/i18n.py`.

## The rules

- **Macedonian is the source.** A string in the code is the Macedonian the customer reads,
  marked `{{ _('…') }}` in a template or `gettext('…')` in Python. Macedonian has no catalog;
  a string with no translation shows its Macedonian, never a key.
- **A language exists when its compiled catalog does.** The planned ones are `sq`, `en`, `tr`
  (CLAUDE.md). A locale is chosen only if `app/translations/<lang>/LC_MESSAGES/messages.mo` is
  on disk. Until then `?lang=sq` gets the Macedonian page, with `<html lang="mk">`: the label
  says what the page *is*, never what was asked for.
- **Choosing**: `?lang=` (remembered in a `lang` cookie for a year), then the cookie, then the
  browser's `Accept-Language`, then Macedonian. There is no visible switcher until a second
  language exists: offering languages with no content would mislead.
- **Albanian waits for a named reviewer** (`decisions.md` D7), and any Macedonian or Albanian a
  model writes passes a person before a customer reads it (CLAUDE.md). A catalog written by a
  model is model output: it is reviewed like one.
- **Dates are `dd.mm.yyyy` in every language** (`format.mkdate`, no locale on purpose).
  **Numbers** group as the language does: `|number` and `|money` (8.900 МКД in Macedonian,
  8 900 in Albanian, 8,900 in English). The unit is always «МКД» (translatable as a word) or
  «EUR», never a currency symbol: it is what the calls write.
- **The institution's words keep their language.** A quote, a call title, a criterion label
  from the registry carries its own `lang` (`|lang_of`, or `lang="mk"`) whatever the page's.

## Adding a language

```bash
uv run pybabel extract -F babel.cfg -o app/translations/messages.pot .
```

```bash
uv run pybabel init -i app/translations/messages.pot -d app/translations -l en
```

Translate `app/translations/en/LC_MESSAGES/messages.po`, then:

```bash
uv run pybabel compile -d app/translations
```

After a template changes, `pybabel update -i app/translations/messages.pot -d app/translations`
carries the catalog forward. The `.pot` is generated, not committed: it is always one extraction
away and a committed one goes stale.

## What is marked, and what is not yet

| Surface | State |
|---|---|
| The shell (`base.html`: navigation, tab bar, skip link, footer) | marked |
| The landing (`index.html`) and the prices (`pricing.html`) | marked, plurals with `ngettext` |
| The intake (`intake/*.html`) and its questions (`app/matching/intake.py`) | **not yet** |
| The shortlist and the passage (`shortlist/*.html`), `_components.html` | **not yet** |
| Verdict and criterion words (`app/web/format.py`), stage 1/2 reasons (`app/wording.py`, `app/matching/`) | **not yet**: Python strings also used outside a request (the PDF), so they need `lazy_gettext` and a check that the PDF still renders in Macedonian |
| The report PDF | Macedonian only: a report in another language is generated prose, D7's question |
| Admin, `/stil`, `/demo` | Macedonian only by design: one operator, a development page, a demo that will be replaced |

Mark the rest before the first catalog ships, or that language's pages mix two languages.
